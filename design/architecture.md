# 전체 구성도

> **공개용:** 내부 IP·상세 연결값은 생략했습니다. 팀내 도면 v1.1·주소표·기술서에서 실제 값을 확인하세요.

**현재 자료:** 토폴로지 v1.1 PDF 12쪽(팀내 공유, 공개 저장소 미게시) · [계획서 v0.3](../plans/project-plan-v0.3.md) · [WBS](../WBS.md)

**상태:** 강사 피드백 반영 구축 전 설계안. 실제 IP·왕복 통신·VPN·외부 API·패킷 미러 검증 전이며, 팀 기술 검토와 초기 실습으로 확정합니다.

- p.1~2: 물리 PC 5대 배치 / M1~M3 각 VyOS·UTM / 교실 GW 교실 GW(팀내 확인값) / AWS 공개 서비스.
- p.3~4: M1 기존 전체 장비 보존. GNS3 access 및 eth3 trunk, 전용 LAN 인터페이스 구분.
- p.5~6: M2 독립 UTM, 외부 포함 NIC 4개, SOC/TEST/MGMT 독립 VMnet. VLAN 없음.
- p.7~8: M3 DMZ/APP/DATA NIC 분리, TO-BE MGMT 추가. AWS React·MP4·VTT·S3 업로드·CDN 재생.
- p.9~10: M4 백업·복제·S3·격리 복원. Bridged 출구는 제안.
- p.11~12: M5 운영/콘텐츠/관리 NIC 분리, 업무 VPN과 공개 Store 분리. VLAN 없음.

UTM 번호: 1=M1, 2=M2, 3=M3, 4=M4, 5=M5. 이전 번호의 공격 안내 이미지를 현재 구성의 설정 근거로 사용하지 않습니다.

K1~K5는 미확정 교실 IP의 기호, transit·VMnet 번호는 제안값입니다. 상세 설정·시험 증거는 각 담당 Notion에 기록합니다.

상세 내부 주소·배선이 담긴 도면 원본은 공개 저장소에 올리지 않습니다. 팀 공유 경로는 PM에게 확인하고 실제 설정·로그는 접근권한이 있는 기술서에 기록합니다.
