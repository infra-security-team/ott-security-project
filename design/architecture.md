# 전체 구성도

**팀명 Blocks · 보안 컨설팅 회사 NetBlocks · 가상 OTT 고객사 OTTer**

> **공개용:** 내부 IP·상세 연결값은 생략했습니다. 팀내 도면 v1.1·주소표·기술서에서 실제 값을 확인하세요.

**현재 자료:** 토폴로지 v1.1 PDF 15쪽(팀내 공유, 공개 저장소 미게시) · [계획서 v0.3](../plans/project-plan-v0.3.pdf) · [WBS](../WBS.md)

**상태:** 강사 피드백 반영 구축 전 설계안. 10/20 회의에서 망별 IP 배정을 확정했습니다. 세부 주소는 팀 주소표를 따르며, 왕복 통신·VPN·외부 API·패킷 미러·CI/CD는 실제 구축 후 검증합니다.

- p.1~2: 물리 PC 5대 배치 / M1 GNS3 R1·UTM / M2·M3 VyOS·UTM / 교실 게이트웨이 / AWS 공개 서비스.
- p.3~4: M1 기존 전체 장비 보존. GNS3 상위 라우터 R1(별도 VyOS 없음), L2 access 및 eth3 trunk, 전용 LAN 인터페이스 구분.
- p.5~6: M2 독립 UTM, 외부 포함 NIC 4개, SOC/TEST/MGMT 독립 VMnet. VLAN 없음.
- p.7~8: M3 DMZ/APP/DATA NIC 분리, TO-BE MGMT 추가. AWS React·MP4·VTT·S3 업로드·CDN 재생.
- p.9~10: M4 백업·복제·S3·격리 복원. Bridged 출구는 제안.
- p.11~12: M5 운영/콘텐츠/관리 NIC 분리, 업무 VPN과 공개 Store 분리. VLAN 없음. 관리 단말 1대 권고, 추가 관리 주소는 확장 예약.
- p.13: GitHub 제공 Actions 실행 서버·이미지 저장소·배포 설정 Git·S3 정적 웹 배포 전체 흐름.
- p.14: 기존 M3 Kubernetes 내부 Argo CD와 Worker 이미지 다운로드·앱 배포.
- p.15: 기존 M5 EKS 내부 Argo CD, 사내 관리 단말과 개발용 Windows PC의 역할 구분.

UTM 번호: 1=M1, 2=M2, 3=M3, 4=M4, 5=M5. 이전 번호의 공격 안내 이미지를 현재 구성의 설정 근거로 사용하지 않습니다.

이전 도면의 K1~K5는 교실망 IP의 임시 기호입니다. 10/20에 확정한 세부 배정값은 팀 주소표에서 확인합니다. T1~T3는 M1의 GNS3 R1–UTM1 및 M2·M3의 VyOS–UTM 연결망이며, T15는 M1–M5 VPN, T14는 M1–M4 VPN, T34는 M3–M4 VPN입니다. 이 임시 표기 자체는 실제 주소값이나 연결 완료를 뜻하지 않습니다. 확정 주소표와 도면을 대조하고 실제 VMnet 연결·왕복 통신을 시험합니다. 상세 설정·시험 증거는 각 담당 Notion에 기록합니다.

상세 내부 주소·배선이 담긴 도면 원본은 공개 저장소에 올리지 않습니다. 팀 공유 경로는 PM에게 확인하고 실제 설정·로그는 접근권한이 있는 기술서에 기록합니다.

최신 계획서는 v0.3(14쪽)입니다. 개요·담당·서비스 흐름은 계획서, 실제 장비 배선은 토폴로지, 명령어·로그는 담당 기술서에서 확인합니다.

**M1 수정:** 교실망 ↔ GNS3 라우터 R1 ↔ UTM1 ↔ 기존 GNS3 VLAN 스위치·서버·PC. UTM1이 내부 게이트웨이·방화벽·VPN을 맡고, R1은 상위 연결만 담당합니다. 라우터 이미지·VMware 연동·VLAN 태그 전달은 실습 전 확인합니다.
