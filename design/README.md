# 설계 자료

인프라 연결은 topology, 데이터 설계는 erd, 프로그램 구조는 classdiagram에서 관리합니다. 애플리케이션 설계는 사내 게시판·OTT 메인·Store를 각각 구분합니다.

| 자료 | 위치 | 관리 범위 |
|---|---|---|
| 토폴로지 | [topology](topology/README.md) | M1~M5 AS-IS와 공격 분석 후 TO-BE |
| ERD | [erd](erd/README.md) | 사내 게시판·OTT 메인·Store의 DB 구조 |
| 클래스 다이어그램 | [classdiagram](classdiagram/README.md) | 사내 게시판·OTT 메인·Store의 클래스와 관계 |

## 작성과 확정

M5가 애플리케이션 요구사항·데이터·클래스 설계를 정하고 코드를 개발·검증합니다. AI 제안은 M5와 검토한 뒤 draw.io에 입력하고, M5가 만든 파일을 확인받아 등록합니다. 확인 전 제안은 최종본으로 취급하지 않습니다.

M1·M2는 각 본사 게시판, M3는 한국 OTT·AI의 인프라 배포와 실행 환경·연결·로그 확인을 담당합니다. M3를 애플리케이션 개발 설계 검토자로 지정하지 않습니다. 인프라 기술 조정 역할은 유지합니다.

## 도면 상태

- 작성본 등록: 작성한 도면이 등록된 상태이며 최종 승인·구현 완료를 뜻하지 않습니다.
- 제안 초안: 아직 M5가 확정하지 않은 자료입니다.
- 최종 확정: M5가 확인한 서비스별 설계본입니다. 이후 변경 시 실제 코드와 대조합니다.

기존 토폴로지 폴더는 2026.10.21에 topology로 이동했습니다. 이전 클래스 v1.0 표기는 최종 확인 없이 등록한 것이므로 철회하고 게시판 drafts로 분리했습니다.
