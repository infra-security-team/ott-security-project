# 02 · 보안 솔루션 배치/구축 책임표 — 5명 모두 보안 구축·재검증

> **v1.2 우선 확인:** [최신 토폴로지·보안 연결·검증 범위](../architecture.md)를 먼저 읽으세요. 아래 상세 내용에는 이전 설계·제안이 남아 있을 수 있으며, 실제 배선·센서·관제 경로는 v1.2 및 팀 확정값과 대조합니다.

> **팀 검토용 기준안.** 보안 소프트웨어를 모든 망에 *동일하게 전부* 설치해야 한다는 의미가 아닙니다. 서비스·공격 시나리오·로그 위치에 필요한 통제 기능을 설치합니다. 관제 통합의 책임은 M2이고, 각 망의 정책 설치·원본 로그·전후 검증은 **각 망 담당자**의 책임입니다.

## 1. 보안 기능·소프트웨어를 어디에 둘 것인가
| 담당/구역 | 각자 직접 구현/확인할 보안 통제 | 중앙 M2와 연동 | 본인의 시험 증거 |
|---|---|---|---|
| **M1 본사 네트워크** | 본사 VyOS 경계 방화벽·VLAN 간 ACL, 관리망 분리, IPsec VPN 허용 대역·NAT 예외·Bastion 접속 정책 | 라우터/방화벽·VPN/접근 차단 로그, 시간 동기화 | S01 직원→관리 직접 접속 AS-IS → 정책 수정 후 차단/승인 관리 허용 |
| **M2 본사 보안·SOC** | 격리 공격 Linux, SSH 시험 서버의 인증/계정 정책, Bastion, 중앙 Wazuh, Suricata **관측 가능한 위치**의 센서 | 중앙 Wazuh 서버 및 에이전트 정책/대시보드, 원본 로그와 비교 | S02 반복 실패 인증의 원본·경보·제한 여부 전후 확인 |
| **M3 한국 서비스망** | VyOS/DMZ 방화벽, 웹/API/DB 관리 포트 접근 통제, OS 보안, 컨테이너/이미지 보안 기본 설정, K8s API 접근/RBAC/NetworkPolicy **실행 가능 CNI 확인** | APP·DB·Linux 로그 에이전트/전송, K8s 감사 로그는 실제 활성화·수집 가능성에 따라 검토 | S03 실제 관리 포트 노출 시험 → 제한 후 서비스/관리 정상 경로 교차 확인 |
| **M4 백업·DR망** | 백업 VLAN·방화벽, DB 백업·복원 서비스 계정/파일 권한, 별도 복원 격리, S3 IAM 최소 권한·비공개 버킷·암호화/로그 | 접근 실패·백업·복원 이벤트 및 S3 로그 수집 가능 범위 합의 | S04 승인된 시험 계정 백업 접근 → 최소 권한 개선·실제 복원 증거 |
| **M5 캐나다망·클라우드** | 캐나다 VyOS 직원/관리 분리·VPN/DB 접근 규칙, AWS IAM·보안그룹(EC2 사용 시)·공개 HTTPS 설정/비밀정보 보호 | 캐나다 VyOS/클라이언트 및 AWS 제공 가능한 로그의 중앙 수집 방식 합의 | S05 캐나다 직원→VPN→한국 DB 직접 접근 재현 → 차단 및 정상 API 성공 |

## 2. 보안 도구별 실제 설치 위치/역할
| 도구·기술 | 어느 곳에 배치하는가 | 최소 검토 사항 |
|---|---|---|
| **VyOS 방화벽/ACL** | M1/M3/M4/M5 각 망의 라우터/경계 장비, 해당 망 담당자가 직접 설정 | AS-IS 취약 조건/TO-BE 차단 조건을 구분. 방화벽 자체가 Wazuh·IDS는 아님 |
| **Wazuh 중앙 서버** | **M2 중심 관제** (성능에 따라 분리 구성 가능) | 실제 CPU/RAM·로그 저장·이벤트 시간·기술 선택 |
| **Wazuh Agent/로그 전송** | M1~M5 해당 Linux/Windows 서버·접근 기록을 수집해야 하는 자산에 담당자가 설치/연결 | 에이전트는 서버마다 가능하지만 모든 **클라이언트/라우터**에 설치를 강제하지 않음. 네트워크 장비 로그는 syslog 등 다른 방법 검토 |
| **Suricata IDS 센서** | 암호 해제 후 트래픽이 보이는 경계·가상 스위치 미러링 지점 등 **관측 가능한 위치** | 망마다 1 VM 강제하지 않음. VPN 암호화 트래픽과 내부 평문 관측 차이, NIC/미러링 지원 확인 |
| **Bastion/관리경로** | 승인 관리자→관리 대상에 필요한 중앙/망별 경로 | 관리 포트는 고객 공개 HTTPS/DB 포트와 분리 |
| **OS·SSH 접근통제** | 각 담당 서버 | 실제 서비스 계정·관리자 범위·인증 로그·시간 동기화 |
| **Docker/K8s 보안** | **M3** 앱 실행·컨테이너/클러스터 경계, **M5** 앱 코드·설정 제공 | 도커 이미지·민감정보 관리, Pod 서비스 계정/RBAC·API 관리 포트, 네트워크 정책 CNI 지원과 적용 전후 결과 |
| **AWS 접근통제** | M4 S3 백업, M5 공개 웹/서비스 경로 | IAM 최소 권한·비공개 S3·HTTPS/TLS, 실습 계정 정책·비용·클라우드 로그 가용성. WAF는 실제 운영 범위/비용 확인 후 선택 |

**WAF는 웹 HTTP/HTTPS 요청을 보호하는 보안 기능이며 방화벽이나 IDS/IPS를 그대로 대체하지 않습니다.** 웹에 적용할 실제 제품/Managed WAF 비용을 검토하되, 합의 없이 필수라고 추가하지 않습니다. IDS는 탐지, IPS/차단은 별도의 실행·검증이 필요합니다.

## 4. 반드시 피할 오해
- **M2만 4개 망 보안을 구축하는 게 아님.** M2는 중앙 관제·표준 조언/연계, 각 망 담당이 직접 구축·변경·재시험.
- **AS-IS도 승인된 격리 환경**에서만 취약한 통신을 열고, AWS 공개 인터넷이나 외부 사용자 접근 가능한 서버에 취약 설정을 노출하지 않음.
- 보안 제품을 설치한 사실 != 탐지·차단 성공. 에이전트 등록, 시간 동기화, 실제 경보, 차단 후 정상 기능을 각각 검증.
- 방화벽 규칙·WAF·K8s NetworkPolicy는 지원 제품과 **실제 실행 위치**를 확인하고 적용. 도면만으로 기능 지원/완료 주장 금지.
