# 00 · 하이브리드 전체 배치·장비 선정 기준

## 1. 혼동하기 쉬운 용어
- **온프레미스(On-premises):** 학원/자체 장비에서 가상화 호스트와 네트워크를 관리하는 형태.
- **가상머신(VM):** 한 물리 호스트에서 가상 OS를 실행하는 형태. VMware VM은 온프레미스에 놓일 수 있고 AWS EC2도 가상 서버를 제공합니다.
- **클라우드:** AWS EC2(컴퓨팅), S3(객체 스토리지), CloudFront(웹 콘텐츠 배포) 같은 서비스 이용. S3는 VM이 아닙니다.
- **하이브리드:** 온프레미스 망과 AWS 서비스를 기능적으로 연결한 구조. **반드시 AWS까지 IPsec VPN으로 연결해야만 하이브리드인 것은 아닙니다.** 고객용 HTTPS 공개 경로와 내부 관리자 VPN 경로를 분리합니다.
- **VLAN:** 한 물리/가상 스위치 위에서 논리적으로 구역을 분리하는 기능. VMware의 VMnet 분리만으로 실제 802.1Q 태깅 구현을 증명하지는 못합니다.

## 2. 1차 배치안: 각 망 담당과 AWS를 나누기

| 영역 | 1차 기본 배치 | AWS 활용/관계 | 주담당·협업 |
|---|---|---|---|
| 한국 본사 직원/관리/보안 구역 | 학원 VMware·vSphere, VyOS VPN 허브, 관리/시험 서버 | 공개 서비스가 아닌 내부 관리·허용 경로 | M1 네트워크 + M2 보안 |
| 한국 서비스 DMZ/APP/DATA | 가상 네트워크, Nginx, **Docker 이미지/컨테이너 배포 경로, Kubernetes Control Plane·Worker·Service/Ingress 설계**, Spring Boot, MySQL | 캐나다/외부 고객 HTTPS 웹에서 API 요청 연결; 보안정책·CORS/TLS 검사 | M3 인프라·배포 + M5 앱 코드 |
| 백업/DR | 별도 VLAN/VPN, 백업 서버, DB 복원 시험 격리환경 | S3에 원격 백업 사본 (버킷 비공개, 권한 최소화) | M4 + M3 |
| 캐나다 지사 직원/관리 | 격리된 실습 VMware/VyOS, 본사 IPsec Site-to-Site VPN | '캐나다 지사' 논리망과 AWS 물리 Region은 별개 | M5 + M1 |
| 캐나다/외부 공개 웹 | 기본적으로 클라우드의 HTTPS 정적 웹/콘텐츠 경로를 우선 검토 | S3(비공개 원본)+CloudFront 등 또는 비용/권한 허용 시 다른 구성 | M5 + M3 |
| 음성 인식·번역 | FastAPI 앱 서버에서 호출/처리 | 외부 API 사용 시 네트워크·키·비용·타임스탬프 확인 | M5 + M3 |

**Docker/Kubernetes 설계는 W1부터 필수 검토 대상**입니다. Docker 이미지 생성/보관·단독 실행 호스트와 Kubernetes 노드/Pod·Service·Ingress 및 관리 접근을 처음부터 그림에 넣습니다. 단, 실제 노드 수·설치 방식·완료 목표는 자원과 강사 피드백 후 확정하며 10/19 설치 완료를 요구하지 않습니다. 각 망 방화벽·로그 연계는 [보안 설치 책임표](02-security-deployment-matrix.md)로 검토합니다.

**확정 전 질문:** 학원 VMware 호스트 CPU/RAM/스토리지, vSphere와 VMware Workstation 네트워크 공유 범위, 가상 스위치 VLAN/트렁크 지원, 인터넷/NAT 가능 경로, AWS 계정 허용 서비스·Region·비용 제한.

## 3. VM 수량은 '최소 논리 역할'이지 사전 확정 대수가 아님
아래 표는 **중복 구축을 막기 위한 첫 요청량**입니다. 설계 승인 후 실제 장비 1대가 여러 역할을 할 수 있으나, 방화벽·관리·시험 격리는 유지해야 합니다.

| 망/담당 | 최소 예시 역할 수 | 수량 기준 |
|---|---|---|
| 본사 M1 | VyOS 허브 1, 직원 클라이언트 1, 관리자 클라이언트 1 | 3개 역할; 관리자 PC는 다른 망의 검증 때 재사용 가능 |
| 보안 M2 | Bastion 1, SSH 시험 대상 1, Wazuh 1, 공격 Linux 1 | 4개 역할; Suricata 관찰 센서는 자원/트래픽 미러링 확인 시 추가 |
| 서비스 M3 | VyOS/경계 1, 웹 진입 1, APP 실행 호스트 1, DB 1 | 4개 역할; 컨테이너·K8s는 대체/확장 배치로 검토 |
| DR M4 | VyOS/경계 1, 백업 서버 1 | 2개 역할; DB Replica/격리 복원 인스턴스는 검증 시점·자원 확인 후 할당 |
| 캐나다 M5 | VyOS 1, 직원 클라이언트 1, 관리자 클라이언트 1 | 3개 역할; 추가 웹 진입 VM은 AWS 웹 구성과 중복 시 불필요 |

**기본 논리 역할 합계: 16** (=3+4+4+2+3). 이는 **16대를 당장 설치하라는 지시가 아닙니다.** 기존 제안의 '17대 기본'은 M4 DB Replica를 기본 포함한 경우였고 실제 선택은 M3·M4 협의로 결정합니다. K8s/센서/복원용 임시 VM 및 AWS EC2는 별도 사전 평가합니다.

### 기능 분류표: '장비'와 '기능'은 다름
| 기능 | 누가/어디에 | 구현 시 주의 |
|---|---|---|
| VLAN·게이트웨이·라우팅 | 각 망 VyOS 또는 검증된 L3 장비 | 망별 대역·가상 NIC·가상 스위치/포트 그룹 관계 확인 |
| 방화벽 | 각 망 경계 VyOS | AS-IS/TO-BE별 허용·거부 규칙표, 정책 순서, 로그, 정상 경로 |
| DHCP | 본사/캐나다 직원 VLAN 우선 | 서버/관리 장비는 일반적으로 고정 IP, 중복 DHCP 서버 금지 |
| DNS | 기존 DNS/라우터 전달 또는 필요한 기능 | DNS 서버를 무조건 VM으로 만들 필요 없음 |
| NAT | 인터넷 출구에서만 필요한 경우 | IPsec 보호 대상에 불필요한 NAT 방지, 왕복 경로 확인 |
| IPsec VPN | 본사 허브와 서비스/DR/캐나다 경계 | IKE/터널 상태뿐 아니라 실서비스 TCP 및 반환 경로 확인 |
| NTP | 모든 서버·장비 | 로그 시간 대조·STT 처리/보안 시험 타임라인 정확성 |
| HTTPS/TLS | AWS 공개 웹과 한국 API 진입점 | 내부 관리/DB 포트를 외부에 공개하지 않음 |
| 로드밸런서/이중화 | M3 APP/웹 운영 | 프로세스 재시작 != 전체 HA, 장애·정상 요청 증거 분리 |
| 백업·복제·DR | M4와 M3 | 복제 성공 != 백업/복원 성공; RPO/RTO 측정 |
| IDS/로그 | M2 Wazuh·Suricata | 센서 관측 경로·원본 로그·탐지/차단 별도 판정 |

## 4. 전체 논리 연결을 도면으로 옮길 때
1. 본사 VPN Hub를 중앙에 두고 서비스·DR·캐나다 망에 Site-to-Site VPN 선을 **각각** 표시합니다(실제 VPN 종단과 인증 방식은 미확정).
2. 서비스망에서는 DMZ → APP → DATA 흐름과 서버별 관리 접근 경로를 다른 선으로 표현합니다.
3. AWS는 '공개 HTTPS 웹 ↔ 한국 API'와 '백업 → S3'라는 **서로 다른 경로**로 그립니다. 경로를 섞거나 AWS가 곧 캐나다 지사 내부망인 것처럼 그리지 않습니다.
4. 화살표에는 출발지, 목적지, 용도, 프로토콜/포트, 허용/거부(AS-IS, TO-BE)를 표시합니다. 포트값은 실제 앱 계약과 실습 조건 후 확정합니다.
5. 방화벽과 VPN은 같은 그림에서 표시하되, 'VPN 통과'와 'DB 직접 접근 허용'을 혼동하지 않습니다.

## 5. 회의에서 반드시 결정할 항목
- 각 망 책임자/작업 시간, 실제 자원과 VM 상한.
- VPN 종단(물리/가상 NIC), VPN 보호 대역, 라우팅/반환 경로·NAT 예외.
- 공개 웹/HTTPS/API, 클라우드 서비스 이용 방식과 예상 청구 비용.
- 5개 공격 시나리오의 실행 가능 범위와 정상 통신 테스트.
- K8s/이중화는 **실제 구현·시연 범위를 검증하고 단계적으로 확장**할지.
- 불가능한 항목의 대체안·결정권자·기한. 결정 내용은 회의록, 본인 실행 결과는 Notion.
