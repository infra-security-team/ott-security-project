## 사용할 프로그램·환경
- **도면:** diagrams.net / **기본 서버:** Linux VM / **접근 관리:** SSH·Bastion
- **관제:** Wazuh 서버/에이전트, 선택한 원본 로그 수집 방식
- **패킷 탐지:** Suricata: SOC 진입 독립 전달 쌍 2 NIC + 관리 1 NIC
- **시험용:** 승인된 공격 Linux, 격리된 SSH 시험 서버, tcpdump / 저널/SSH 원본 로그
- 설치 전 Wazuh·Suricata 최신 지원 OS/자원 요구사항 및 실제 센서가 VPN 암호화 트래픽을 어디서 볼 수 있는지 검토.

| HQ-SSH-Test | 1 VM | 정상 SSH 및 반복 인증 실패 S02 시험 대상 | 별도 계정/격리 환경; 서비스 운영서버에 실험 금지 |
| HQ-Wazuh | 1 VM 또는 조건부 분리 | 중앙 로그·경보 | RAM/디스크 요구량 확인. 기능과 가상머신 수 동일 아님 |

## 10/19 AS-IS 도면 체크
- [ ] 공격/관리/직원 구역과 SSH 대상·Bastion·Wazuh의 실제 위치
- [ ] 원본 로그 발생 장비 → 수집기/서버(포트·시간 동기화) 방향
- [ ] 정상 관리자 SSH 경로와 S02 반복 인증 실패 시험 경로를 **서로 다르게** 표시
- [ ] 센서 배치/관측 가능한 구간(암호화 IPsec **안쪽/바깥쪽**에 따라 관찰 범위 다름)
- [ ] 10/20 합의할 시험 조건: 격리, 허용 시간/횟수/계정, 로그 종류·성공 판정, 롤백
- [ ] TO-BE 초안: 인증 강화·불필요한 접속 제한·관제/경보 개선 방향. 시험 전 적용 금지

## 구축·검증 우선순위
1. M1과 IP·라우팅·관리 ACL 합의 → 기본 Linux 설치/시간 동기화.
2. 승인 관리자에서 Bastion/시험 서버로 정상 접근 검증.
3. Wazuh 등 중앙 로그 수신, 원본 SSH 로그와 이벤트 시간 교차 확인.
4. AS-IS 정상 기능 확인 뒤 **승인된 격리 환경의 제한된 인증 실패 재현**, 경보 발생/차단 여부 구분.
5. 원인 분석 → TO-BE 개선 → 동일 횟수·입력 조건 재검증. M2가 다른 망 보안을 모두 대신 수행하지 않음.

**증거:** 서비스/에이전트 프로세스, 수신 로그 타임스탬프, 탐지 결과, 정상 로그인 성공, 미수신 경로·센서 한계. [막힐 때 확인](troubleshooting.md).
