# 망별 구축·통신·보안 장애 공통 점검

> **기본 원칙:** 도면을 그린 것과 실제 망이 동작하는 것은 별개입니다. 각 단계에서 '계획 / 미수행 / 성공 / 실패 / 재검증'을 구분합니다. 의도적인 취약 설정이나 공격은 승인된 **격리된 실습 대상**만 사용합니다.

## 1. 도움을 요청하기 전에 이 순서로 좁혀 보기
| 문제 | 먼저 확인할 사실 | 필요한 증거/협업 |
|---|---|---|
| VM 부팅/자원 부족 | 실제 가상화 플랫폼, CPU/RAM/디스크, VM 콘솔 오류 | 호스트 자원·VM 설정 캡처 → 담당자/PL |
| 직원 PC IP 없음(DHCP) | VM NIC↔가상 스위치/포트그룹, VLAN/서브넷, DHCP 서버/범위 | 클라이언트 IP·게이트웨이·DHCP 관련 로그 → 담당 망 |
| 같은 VLAN 통신 실패 | NIC 상태, IP/넷마스크, 같은 가상 스위치/포트그룹 | 로컬 IP·ARP·패킷 캡처 |
| 다른 VLAN 접근 실패 | 기본 게이트웨이, L3 라우팅, ACL/방화벽 | 양단 라우팅 테이블·차단 로그 |
| VPN은 up인데 통신 불가 | 보호 대역, 양쪽 라우트/반환 경로, NAT 예외, 방화벽 | 양단 VPN 상태·패킷/로그 비교 → M1+상대 망 |
| DNS만 실패 | IP 직접 연결 결과 vs 도메인 조회, DNS 전달 경로 | nslookup/dig 결과, DNS 주소 |
| React는 보이지만 API/DB 실패 | 브라우저→CloudFront(S3 정적 자원)과 브라우저→승인된 HTTPS API 진입점→프록시/Spring→DB를 분리 점검; TLS·CORS·바인드/포트·DB 권한 확인 | 브라우저 Network 탭·API 응답·서버/DB 로그 → M3+M5 |
| 로그가 Wazuh에 없음 | 서버 시계, 에이전트 상태, 출발지/수집 포트, 실제 관찰 지점 | 원본 로그·중앙 수신 시각 → M2+원본 소유자 |
| S3 사본/복원 실패 | 버킷 권한·암호화·객체 경로·잔액, 파일 무결성·DB 버전 | 오류코드(키/토큰 비공개), 체크섬·복원 로그 → M4+M3 |
| 보안 시나리오 미재현 | 정상 경로·공격 출발지·대상·기대 결과·설정 근거 | '미재현' 그대로 기록. 조건/승인 범위 검토 → PL·해당 망 |

## 2. Linux 확인 명령 예시(서버 OS/배포판에 맞게)
아래는 **읽기 중심 기본 상태 확인**용. VyOS와 Windows에는 다른 명령을 사용합니다.

```bash
ip -br addr       # 내 NIC·IP 상태
ip route          # 기본 게이트웨이·경로
ip link show      # 링크 up/down 여부
ping -c 3 <GATEWAY_IP>    # 확정된 랩 게이트웨이 대상, 3번 제한
getent hosts <AUTHORIZED_HOSTNAME>  # DNS 확인
ss -lnt           # 서버가 듣고 있는 TCP 포트
```

VPN 방화벽 정책은 '터널 활성'과 '정상/금지 TCP 경로 성공'을 분리 확인합니다. 기본 네트워크 시험에 실패하면 공격/TO-BE 검증 성공으로 기록하지 않습니다. 공개 서버 스캔·무차별 인증 시도 등 승인되지 않은 테스트 금지.

목표 / 정상이어야 하는 경로:
실제 출발지(구역·가상 NIC) → 목적지(구역·서비스/포트):

확인한 설정·출력(비밀값 마스킹):
지금까지 시도한 점검과 결과:
막힌 원인(확인 사실) / 원인 추정(구분):
영향받는 다른 업무·Issue:

증거(설정, 라우팅, 로그, 캡처·도면 버전 링크):
