## 10/19~23 일정의 현실성 판정과 잠정 합의
- 10/19 피드백·설계 초안, 10/20 공동 검토, **10/21 오전 구축 가능한 설계 기준선** 목표. 수정 요구가 큰 부분은 미확정으로 관리.
- **10/21 오후~10/23 실제 첫 AS-IS 구축 착수**(늦어도 목요일). W1 안에 4망·K8s·Wazuh·AWS 전체 설치가 완료되는 것으로 간주하지 않음.
- **10/28** 4망 VPN 정상/비인가 경로, M3 Kubernetes 자원·실제 실행 대상, M5 로컬 OTT 기본 기능 중간검증.
- **10/30:** M1·M2·M4 승인 공격 3건 증거, **M3·M5 AS-IS 앱 최소 배포/정상 동작** 검증. 계획서 v0.2의 10/30 공격 5건 목표와 차이는 강사 검토 사항. K8s API S03·VPN→웹→APP IPS S05는 정상 서비스·대상·로그 준비 후 11/02 진행.
- **11/02:** M3 S03·M5 S05 승인된 격리 공격 2건, 전체 5건 증거 취합. 실제 시험 불가 항목은 '미수행' 처리하고 11/03 TO-BE 변경 전 원인 검토.
- 11/03~06 TO-BE+AI 자막+AWS/S3/복원 1차; 11/09~10 동일 조건 재검증/복원·장애 시험; 11/11~13 발표 증거/자료 정리; 11/16 최종 발표.

## 최우선 작업 병목
1. M5: 캐나다 VPN+React/Spring/MySQL/FastAPI+PM을 병행. 10/22~23 개발 골격 → 10/28 로컬 최소 기능 → 10/30 배포·정상 서비스 → 11/06 실제 STT/번역은 **고위험 연속 마감**. 화면 최소화, 표본 영상 1개, 표본 계정/데이터 및 API 최소 경로로 범위 제한.
2. M3: vSphere/ESXi+3노드 K8s+LB+DB+PL+M5 코드 배포·보안 시험. 실제 CPU/RAM/스토리지 부족 시 대체안을 10/21 이전 강사에게 확인. 앱 코딩은 M5 소유, M3에게 재배정하지 않음.
3. M4: Replica 구축과 파일 백업 환경은 선행 구축, **실제 백업 복원 결과는 11/04~10**. 기존 #29를 10/28 복원 성공으로 잘못 판단하지 않음.
4. M2: 중앙 수집 경로의 실제 연결/로그 증거가 필요하고 Wazuh 서버·Suricata 관찰 지점의 자원/실행 가능성을 검토해야 함. 다른 4개 망의 보안 설치를 혼자 대행하지 않음.

**아직 실행 전:** 10/19 강사 피드백·최종 가상화 장비 사양·AWS 권한/비용/모델 API 지원·실제 프로그램 버전·망별 IP/VLAN·Notion 개인 링크는 미검증 또는 미확정입니다.
