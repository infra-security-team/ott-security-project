# AS-IS / TO-BE 네트워크 설계·구축 가이드

> **현재 상태:** 설계·구축을 돕는 **제안**이며 장비 배치·주소·공격 결과가 확정/구축/검증되었다는 뜻이 아닙니다. 5개 공격 시나리오는 승인된 격리 랩에서만 시험합니다.

## 이 폴더의 목적
팀원이 자기 망을 처음 설계할 때 **무슨 장비/서비스/클라이언트가 필요한지, 어떤 프로그램을 사용하고 어떻게 연결·확인할지** 빠르게 찾는 공간입니다. 실행 명령, 실제 IP, 오류·스크린샷 및 시험 증거는 개인 Notion 기술서에 기록합니다.

**10/19~21 오전까지 3일 안에 AS-IS 구성도·자원 목록·하이브리드/컨테이너/보안 배치안을 완성하는 것이 목표입니다.** 19일 강사 v0.2 피드백을 반영하고, 20일 AS-IS와 TO-BE 방향을 함께 검토합니다. **21일 오후부터 실제 AS-IS 구축에 착수하고 늦어도 22일 시작**합니다. 설계 변경이 필요한 부분만 유보하며, 승인된 독립 구역부터 구축합니다. 실제 공격 재현 뒤 TO-BE 정책을 최종 확정/적용합니다.

## 운영 원칙
- 모든 항목을 별도 VM으로 만들지 않습니다. VyOS 1대가 라우팅·DHCP·NAT·방화벽·VPN을 **함께** 수행할 수 있고, 클라우드에서는 AWS 관리형 서비스를 이용할 수 있습니다.
- 'VM = 온프레미스'가 아닙니다. VMware의 VM과 AWS EC2 가상 서버는 배치·관리 경계가 다릅니다.
- **필수/조건부/미확정**을 구분합니다. 서비스용 PC·복원 시험 노드·Kubernetes 추가 노드·AWS EC2는 필요성/비용 확인 후 수량을 정합니다.
- VPN, 방화벽, VLAN, IDS/IPS, NAT는 목적이 다릅니다. VPN이 연결돼도 필요한 통신만 허용하는 접근통제가 별도로 필요합니다.
- 설계도는 **의도한 구조**, 설정/라우팅/패킷/로그 캡처는 **실제 구조의 증거**입니다. 두 자료가 다르면 실제 값을 우선해 도면을 수정합니다.
- AWS는 실습 계정의 실제 권한·지역(Region)·잔액·비용 경보를 확인합니다. 120달러 크레딧은 자동 비용 차단을 의미하지 않습니다.
- 공개 GitHub·공개 도면에는 계정 비밀값, VPN PSK, 키, 실제 접근 가능한 공격 대상 연결 정보를 넣지 않습니다. 사설 IP를 공개할 필요가 있더라도 실습 환경의 공개 범위를 검토합니다.

## 문서 책임
각 담당은 자기 망 명세와 도면의 초안을 작성합니다. M1은 4망의 주소·VLAN·VPN 연결 계약을 취합하고 M3(PL)는 서비스·기술 의존성을 검토합니다. M5(PM)는 회의·일정·미확정 항목과 후속 의사결정을 관리하며 기술 구성을 혼자 확정하지 않습니다.

**문서 업데이트:** 계획에서 설치/검증 단계로 이동했다면 실제 버전·VM명·자원·도면 링크·시험 결과를 Notion 및 Issue에 갱신하고, 합의된 변경만 GitHub 설계도/요약에 반영합니다.
