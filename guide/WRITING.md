# 기술서·최종 보고서 작성 기준

## 개인 기술서 — Notion

**작성자:** 각 팀원. **기록 시점:** 설계·실습·시험 중. **최종 용도:** 다섯 명의 기술서를 합쳐 제출할 상세 설계·구현·검증 보고서.

| 기록 항목 | 작성 내용 |
|---|---|
| 담당과 목표 | 맡은 장비·망·기능, 관련 작업 번호, 해결할 문제 |
| 설계 | 개선 전/후 구성 그림, 주소·연결, 선택한 이유 |
| 구축 | 사용한 버전·명령·코드·설정, 적용 위치, 실패와 수정 과정 |
| 보안 시험 | 출발지·대상·입력·날짜·환경·기대 결과·실제 결과·원본 근거 |
| 개선과 재시험 | 달라진 설정, 같은 조건으로 다시 확인한 결과, 정상 기능 영향 |
| 한계와 기여 | 미구현·미검증 사항, 협업 상대, 본인이 수행한 범위 |

[임시 작성 항목](../docs/templates/technical-detail-template.md)은 팀 Notion 양식 공유 전 참고 자료. 공용 Notion 링크와 접근 상태는 [팀 링크](LINKS.md)에서 확인.

## GitHub 공통 자료

실행할 코드·설정의 원본은 실제 담당 폴더에 저장. 공통 설계·보안 시험·결과 요약은 [문서 목록](../docs/README.md)의 해당 범주에 저장. 개인 기술서를 그대로 다시 붙여넣는 작업은 불필요. 각 문서의 첫머리에 **담당 / 계획·적용·시험 상태 / 관련 작업 번호 / Notion 상세 링크** 표시.

## 최종 보고서 통합

공통 목표·구성도 → M1~M5 설계·코드·설정 → 개선 전후 비교 → 통합·복원·정상 서비스 시험 → 잔여 위험·한계·5인 기여. 각 작성자의 사실 확인, PL의 기술 연결 확인, PM의 누락·일정 확인. 제출 형식·분량은 강사 확인 필요.

**구분:** “구성 완료”와 “시험 통과”는 다른 상태. 로그가 보인 것과 공격 차단도 다른 결과. 실제 확인한 범위만 결과로 기재.
