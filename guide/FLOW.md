# 프로젝트 진행 단계

| 단계 | 팀의 작업 | 다음 단계 전 확인 |
|---|---|---|
| 1. 보안 문제·시험 설계 | 무엇이 문제인지, 어느 장비를 어떤 조건으로 시험할지 정의 | 담당·대상·판정 기준·실습 환경 격리 합의 |
| 2. 개선 전 환경 | 계획한 취약 설정과 정상 OTT 서비스 구축 | 정상 연결·기능과 개선 전 설정 보존 |
| 3. 문제 확인 | 승인된 실습에서 시험, 로그·화면·원인 기록 | 실제 재현 여부와 영향 확인 |
| 4. 개선안 | 원인에 맞는 정책·설정·솔루션과 정상 서비스 영향 검토 | 담당·연동 담당의 적용 방법 확인 |
| 5. 개선 환경 | 방화벽·권한·탐지·백업 등 개선 적용 | 적용 파일·설정 차이·되돌리기 방법 기록 |
| 6. 같은 조건 재시험 | 개선 전과 같은 출발지·대상·입력으로 시험; 정상 서비스도 확인 | 전후 결과·로그·남은 위험 확인 |
| 7. 결과 보고 | 구성도·설정·코드·시험 결과·5인 기여 통합 | 구현·미구현·검증·미검증 구분 |

**병행 가능:** 각자의 설계·앱 개발·기술서 작성. **함께 맞출 조건:** 주소·VPN(M1↔M5), 앱 실행·DB(M3↔M5), DB 백업·복원(M3↔M4), 로그 수집(M2↔전원).

개선 전 환경을 **AS-IS**, 개선 후 환경을 **TO-BE**라고 부름. 다른 환경에서 재시험하면 장비·설정 차이를 기록. 세부 마감은 [일정표](../docs/01-planning/wbs.md), 결과 작성은 [작업·작성 방법](WORK.md) 참고.
