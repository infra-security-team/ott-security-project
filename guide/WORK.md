# 매일 작업·작성 방법

## 1. 기록 위치

| 위치 | 적을 내용 | 백업 작업 예 |
|---|---|---|
| **Notion 기술서** | 목표, 설계 그림, 사용한 명령·코드, 설정 이유, 오류·해결, 실제 시험 화면과 결과 | 백업·복원 명령, 결과 화면, 복원 전후 데이터 비교 |
| **GitHub 담당 폴더** | 팀이 재사용할 실제 코드·설정 원본, 필요한 경우 공통 그림·결과 요약 | 비밀값을 제거한 `backup.sh`, 실행 방법 |
| **GitHub 작업 페이지(Issue)** | 현재 상태, 끝낸 항목, Notion·파일·시험 결과 링크, 다음 행동 | “백업 파일 생성 완료 / 복원 시험 대기”와 각 자료 URL |

같은 상세 설명을 두 곳에 다시 쓰지 않음. **Notion의 코드와 GitHub 실제 파일이 달라지면 기술서 수정 날짜·파일 링크도 갱신.** 코드 파일이 아직 없다면 없는 그대로 기록.

## 2. 작업 페이지 관리

- **본문 수정:** 담당·기한·현재 상태·체크 항목·최신 결과 링크. 본문 오른쪽 메뉴의 Edit 사용.
- **댓글 추가:** 날짜별로 한 일, 문제, 시도, 필요한 도움. 이전 기록 보존.
- **상태:** 할 일 / 진행 중 / 막힘 / 검토 요청 / 완료.
- **체크:** 실제 끝낸 항목만 담당자가 표시. 전체 완료 전에는 작업 페이지를 닫지 않음.
- **검토:** 함께 연결되는 영역의 담당자가 결과 확인. PM은 일정·막힘 조율, PL은 기술 연결 확인. 모든 기술 작업을 PM 혼자 승인하지 않음.

```text
오늘 한 일:
자료 링크: <Notion 구간 URL> / <GitHub 파일 URL>
막힌 점 또는 필요한 도움:
다음 행동:
```

**결과 링크의 뜻:** 다른 팀원이 눌러 원본을 볼 수 있는 정확한 주소. “완료”라는 말만으로 시험 성공 판정 불가. 시험 날짜·환경·기대·실제 결과·근거 필요.

## 3. GitHub 파일 등록 시

| 순서 | 작업 |
|---|---|
| 1 | [폴더 안내](FOLDERS.md)에서 파일 위치 확인. 예: 백업 스크립트 → `infrastructure/m4-backup-dr/` |
| 2 | 브라우저의 Add file 또는 Edit로 작성. 비밀번호·키·실제 백업 데이터 제거 |
| 3 | 변경을 별도 브랜치에 저장하고 PR(변경 검토 요청) 작성. 관련 작업 번호 `Refs #번호` 기재 |
| 4 | 연동 담당자 검토 후 반영. 반영된 파일 URL과 시험 근거를 작업 페이지에 연결 |

처음에는 파일이 없는 설계·실습도 가능. 그날 기록한 Notion 구간을 작업 페이지에 연결하고, 팀 공유 파일이 생긴 때 위 절차 적용. 현재 만들어진 작업은 [일정표](../docs/01-planning/wbs.md)에서 찾고 중복 생성하지 않음.

**막힘 기록:** 하려던 일 / 실제 오류 / 이미 해본 것 / 필요한 정보·사람. 기술 연결은 PL·연동 담당, 일정·장비 충돌은 PM에게 알림.
