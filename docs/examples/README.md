# 작성 예시 · Issue와 산출물·증거 연결
[작업 작성법](../WORK_GUIDE.md) · [폴더 지도](../FOLDER_GUIDE.md)

> **아래는 형식을 이해하기 위한 가상 예시입니다. 실제 시험 결과가 아닙니다.** URL 자리표시자는 실제 주소로 바꿉니다.

## 예시 1 · Issue 본문에서 보이는 내용
| 항목 | 작성 예 |
|---|---|
| 제목 | [M1][W3] M1-04 직원망의 관리 서버 직접 접근 제한 |
| 담당 / 검토 | M1 유용수 / M2 관리 경로 확인 |
| 상태 | 검토 요청 |
| 선행 | M1-03 개선 전 결과 Issue URL |
| 목표 | 직원망의 관리 서버 SSH 접근을 제한하고 Bastion 관리 경로 유지 |
| 산출물 | `infrastructure/m1-hq-network/`의 변경 설정 파일 URL 및 PR URL |
| 증거 | Notion의 S01 시험 구간 URL, GitHub 전후 비교표 URL |
| 완료 조건 | 비인가 경로 제한 + 정상 관리 경로 유지 + 로그·실제 결과 교차 확인 |

### 작업 체크리스트 예시
- [x] 개선 전 설정·시험 결과 보존
- [x] 정책 변경안 및 롤백 방법 검토
- [x] 정책 적용과 시험 결과 기록
- [ ] M2의 정상 관리 경로·증거 검토

마지막 항목이 남았으므로 **완료가 아니라 검토 요청**입니다. 체크마크는 이 예시 안에서만 사용한 설명입니다.

## 예시 2 · 작업을 마친 뒤 남기는 댓글
```text
[가상 작성 예시]
수행: 직원 VLAN의 관리 서버 SSH 직접 접근 제한 규칙 적용.
결과: 같은 직원 단말의 TCP 22 연결이 거부됨. 승인 관리 경로는 접속 유지.
산출물: <변경 설정 파일 URL>, <PR/커밋 URL>
증거: <Notion S01 재시험 구간 URL>, <GitHub 전후 비교표 URL>
남은 일: M2의 로그·관리 경로 교차 확인.
다음 행동: 확인 후 S01 검증 Issue와 연결.
검토 요청: M2 — 출발지·대상·시각 및 정상 접속 증거 확인.
```

“GitHub에 본인이 한 부분을 표로 다시 쓴다”는 의미가 아닙니다. **위처럼 짧은 결과와 원본 링크만 연결하면 됩니다.**

## 예시 3 · Notion 기술서의 시험 기록
| 항목 | 들어갈 내용 |
|---|---|
| 시험 ID·일시 | S01-T02 / 실제 수행 일시·시간대 |
| 환경 | OS·설정 버전·정책 커밋 |
| 출발지·대상 | 시험 직원 단말 → 지정 관리 서버, TCP 22 |
| 입력·기대 | 승인된 연결 시험 / TO-BE에서 직접 접근 거부 |
| 실제 결과 | 실제 출력·응답과 관찰한 로그를 그대로 기록 |
| 정상 기능 | 승인 관리 경로의 접속 결과 |
| 증거 | 캡처·로그·관련 설정 URL |
| 판정 | 통과 / 실패 / 미수행 / 조건부 통과 및 이유 |

캡처에는 **어느 장비·어떤 시험·무슨 결과인지** 설명을 붙입니다. 개인정보·키를 마스킹하고 원본 로그와 시각을 대조합니다.

## 예시 4 · 막혔을 때 댓글
```text
상태: 막힘
증상: 지사 VPN 터널은 연결되지만 한국 시험 서버 응답 없음.
시도: 양쪽 라우팅·정책·대상 서비스 상태 확인.
증거: <점검 로그와 환경 정보 URL>
필요한 도움: M1과 반환 경로·대역 합의 확인.
다음 행동: 경로 확인 전까지 캐나다 정책표와 S05 시험 조건 정리.
```
원인을 아직 확인하지 않았다면 “방화벽 문제”처럼 단정하지 않습니다.

## 산출물·증거·상태의 차이
| 말 | 의미 | 예 |
|---|---|---|
| 작업 상태 | 지금 어느 단계인가 | 진행 중, 검토 요청 |
| 산출물 | 실제 만든 결과물 | 설정 파일·스크립트·구성도·진단서 |
| 증거 | 결과가 동작했는지 확인하는 자료 | 시험 로그·캡처·실제 출력·테스트 기록 |
| 링크 | 다른 팀원이 원본을 열 수 있는 주소 | 정확한 파일/PR/Notion 구간 URL |

파일을 올린 사실만으로 실험 성공이 증명되지는 않습니다. 결과 파일과 동작 증거를 연결해야 합니다.
