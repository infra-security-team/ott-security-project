## 지금 가장 먼저 할 일
장비 자원·가상화 가능 여부·K8s 노드 배치를 확인하고 M5와 실행 계약, M4와 DB·복원 조건을 합의합니다.
- 준비할 산출물: **서비스 배치·자원표, 실행 계약 초안, S03 시험 설계**
- 먼저 받아야 할 정보: M5의 앱 실행 조건·스키마, 실제 장비 자원
- 교차 확인: M5 (앱 통합), M4 (DB 복원), M2 (보안 증거)
- 기본 범위: DMZ·APP·DATA, Linux·MySQL·vSphere·K8s·LB·배포 및 APP 복구. 애플리케이션 코드 작성은 M5.

## 내 작업 순서
| WBS | 시점 | 할 일 | 완료 근거 |
|---|---|---|---|
| M3-01 | W1 | 설계·S03 · DMZ → Kubernetes 관리 포트 6443 과다 노출 조건 작성 | 구성·시험 조건·정상 경로 검토, 미확정 항목 담당/기한 |
| M3-02 | W2 | 서버·DB·컨테이너 런타임과 기본 앱을 배포, 정상 요청을 확인 | 정상 경로 동작·격리 확인, 설정·환경 기록 |
| M3-03 | W2 | 승인된 보안 시나리오 재현·분석 | 관찰 결과·로그·설정·원인/영향 |
| M3-04 | W3 | 개선안 작성 → 관리 경로·권한을 제한하고 정상 API·관리 작업 및 APP 장애 복구 확인 | 검토된 정책·적용 설정 차이·롤백 방법 |
| M3-05 | W4 | 같은 조건 재시험 + 정상 기능 확인 | 전후 비교·정상 기능·잔여 위험 교차 확인 |
| M3-06 | W4 | 결과보고·시연·담당 기여 정리 | 결과 링크·재현 절차·제약 설명 |

M3-02는 COMMON-01 설계 기준선 합의 후, -03은 -02의 정상 기능 확인 후 시작합니다. -04는 -03의 증거 확보 후, -05는 개선 적용 후, -06은 결과가 정리된 후 마무리합니다.

## 재검증 때 유지할 정상 기능
고객 HTTPS/API 요청 및 승인 관리자의 관리 작업. 개선 전·후 같은 입력으로 검사하고 결과를 남깁니다.
K8s가 불가능해 S03을 서버 SSH 접근 시험으로 바꾸려면 PL·M2·팀이 대체 범위를 합의하고 계획 변경을 기록합니다. 조용히 시험 대상을 바꾸지 않습니다.
