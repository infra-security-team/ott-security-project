## 설계 준비
M3와 DB 버전·백업 방식·복원 데이터 확인법을 정하고, DR/격리 복원 구역과 S3 보관 경로를 설계합니다.
- 준비할 산출물: **복제·백업·복원 설계, RPO/RTO 목표 제안, S04 시험 설계**
- 먼저 받아야 할 정보: M3의 DB 버전·데이터 구조, AWS 계정·비용 합의
- 교차 확인: M3 (DB 일관성·복원), M2 (접근 감사)
- 기본 범위: DR VLAN·VPN, DB 복제·백업·암호화·S3 전송·격리 복원.

## 단계별 작업
| WBS | 시점 | 할 일 | 완료 근거 |
|---|---|---|---|
| M4-01 | W1 | 설계·S04 · 비인가 시험 계정의 테스트 백업 파일 읽기 조건 작성 | 구성·시험 조건·정상 경로 검토, 미확정 항목 담당/기한 |
| M4-02 | W2 | 테스트 DB 복제·백업과 별도 복원 환경 준비 | 정상 경로 동작·격리 확인, 설정·환경 기록 |
| M4-03 | W2 | 승인된 보안 시나리오 재현·분석 | 관찰 결과·로그·설정·원인/영향 |
| M4-04 | W3 | 개선안 작성 → 백업 권한·보관 정책을 제한하고 실제 복원·데이터 대조·시간 측정 | 검토된 정책·적용 설정 차이·롤백 방법 |
| M4-05 | W4 | 같은 조건 재시험 + 정상 기능 확인 | 전후 비교·정상 기능·잔여 위험 교차 확인 |
| M4-06 | W4 | 결과보고·시연·담당 기여 정리 | 결과 링크·재현 절차·제약 설명 |

M4-02는 COMMON-01 설계 기준선 합의 후, -03은 -02의 정상 기능 확인 후 시작합니다. -04는 -03의 증거 확보 후, -05는 개선 적용 후, -06은 결과가 정리된 후 마무리합니다.

## 개선 후에도 유지할 정상 기능
승인 계정으로 백업을 읽어 격리 DB에 복원하고 앱 조회 확인. 개선 전·후 같은 입력으로 검사하고 결과를 남깁니다.


S04는 실제 개인정보가 없는 테스트 백업으로 수행합니다. AWS 업로드만으로 복구 완료를 표시하지 않고 내려받은 사본의 실제 복원을 확인합니다.
