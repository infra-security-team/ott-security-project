## 담당 범위·전체 일정
## 설계 준비
캐나다 직원/관리/진입 구역을 설계하고 M1과 VPN, M3와 API·DB 스키마·환경변수·실행 버전을 합의합니다.
- 준비할 산출물: **캐나다 구성안, API·앱 실행 계약, S05 시험 설계**
- 먼저 받아야 할 정보: M1의 VPN 정책, M3의 런타임, AWS·모델 비용 합의
- 교차 확인: M1 (VPN), M3 (배포·서비스 통합), M2 (보안 증거)
- 기본 범위: 캐나다 VLAN·VPN·방화벽 + React·Spring Boot·MySQL 연동 코드·FastAPI·STT/LLM. PM으로 일정·막힘 조율.

**앱 개발은 첫 주부터 [COMMON-03 #8](https://github.com/infra-security-team/ott-security-project/issues/8)에서 병행합니다.** 망 구축 단계가 올 때까지 코드를 기다리지 않습니다. PM 업무와 개발 업무의 소요를 나누어 기록하고 과부하는 팀과 조정합니다.

## 단계별 작업
| WBS | 시점 | 할 일 | 완료 근거 |
|---|---|---|---|
| M5-01 | W1 | 설계·S05 · 캐나다 직원망 → VPN → 한국 MySQL 3306 직접 접근 조건 작성 | 구성·시험 조건·정상 경로 검토, 미확정 항목 담당/기한 |
| M5-02 | W2 | 지사망·VPN과 기본 OTT 코드를 준비하고 M3와 배포 통합 | 정상 경로 동작·격리 확인, 설정·환경 기록 |
| M5-03 | W2 | 승인된 보안 시나리오 재현·분석 | 관찰 결과·로그·설정·원인/영향 |
| M5-04 | W3 | 개선안 작성 → 직원망 DB 직접 접근을 제한하고 정상 웹 서비스·AI 자막 통합 확인 | 검토된 정책·적용 설정 차이·롤백 방법 |
| M5-05 | W4 | 같은 조건 재시험 + 정상 기능 확인 | 전후 비교·정상 기능·잔여 위험 교차 확인 |
| M5-06 | W4 | 결과보고·시연·담당 기여 정리 | 결과 링크·재현 절차·제약 설명 |

M5-02는 COMMON-01 설계 기준선 합의 후, -03은 -02의 정상 기능 확인 후 시작합니다. -04는 -03의 증거 확보 후, -05는 개선 적용 후, -06은 결과가 정리된 후 마무리합니다.
