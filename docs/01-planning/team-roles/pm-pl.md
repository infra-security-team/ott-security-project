# PM·PL의 실제 업무
[WBS](../wbs.md) · [착수 확인표](../readiness.md)

문서가 준비되어 있어도 합의·진행·검토·문제 해결은 팀의 실제 업무입니다. 작성된 계획을 읽고 이해한 뒤 팀 상황에 맞게 판단하고 변경 이유를 남깁니다.

| 상황 | PM · M5 유은혜 | PL · M3 홍은서 | 각 담당 |
|---|---|---|---|
| 10/19 착수 | 목표·기간 설명, 계정·공용 링크·담당 확인, 미확정 사항 담당/기한 지정 | 장비·버전·통신·배포 조건 확인, 기술 의존성 설명 | 자기 첫 작업·산출물·검토 상대 설명 |
| 매일 시작 | 지연·막힘과 다른 사람에게 미치는 영향 확인 | 연동 충돌·기술 장애의 해결 순서 조정 | 자기 Issue의 다음 항목 선택 |
| 작업 중 | 일정·범위 변경 조율, 필요한 지원 연결 | 공동 실행 계약과 기술 일관성 검토 | 직접 구축·기록·시험 수행 |
| 검토 요청 | 누락된 검토자·기한 조정 | 통합 관련 결과 검토, 영역별 검토자 연결 | 연동 담당이 근거 확인·보완 요청 |
| 주간 마감 | 계획 대비 진행·남은 위험 정리 | 실제 통합·시험 결과와 기술 제약 정리 | 결과 파일·다음 단계 인계 |
| 발표 준비 | 제출·발표 순서·시간·리허설 조율 | 구성도·결과·주장의 기술 정확성 점검 | 담당 문제·해결·근거 직접 설명 |

## 짧게 운영하기
- 매일 시작: 각자 오늘 할 일·막힌 점을 Issue로 공유합니다. 별도 일일 보고표를 만들지 않습니다.
- 종료: 작업자가 체크리스트와 결과 링크를 갱신합니다.
- 매주 금요일: 10/23 설계, 10/30 재현, 11/06 개선·통합, 11/13 리허설을 검토합니다.
- 미해결 막힘은 다음 근무일까지 PM이 담당·다음 시도를 정하고, 기술 대안은 PL과 해당 담당이 검토합니다.
- 기술 작업의 완료는 근거를 본 검토자가 확인합니다. PM 혼자 모든 항목에 체크하지 않습니다.
- M3의 서비스 구축과 M5의 앱 개발도 실제 작업 시간입니다. 조율 업무 때문에 밀리면 선택 기능·일정을 조정합니다.

## PM이 처음 직접 적어 볼 내용
`결정할 사항 / 선택지 / 영향 / 담당 의견 / 결정 / 담당·기한` 형식으로 착수회의 결정 기록을 작성합니다. 예: “AWS 비용 상한은 미확정, M5가 사용량 가정 제시, 팀이 10/23까지 결정.” 합의 전에는 승인됨으로 쓰지 않습니다.

PL은 `연동 대상 / 필요한 정보 / 일치하지 않는 설정 / 수정 담당 / 재확인 시점`을 실행 계약·통신표에 기록합니다.
