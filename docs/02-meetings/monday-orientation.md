## 설명 후 각자 직접 해볼 것
- 내 Issue를 찾아 첫 작업과 완료 기준을 말한다.
- Notion 기술서를 열거나 미등록 문제를 기록한다.
- “착수 확인 / 첫 작업 / 필요한 정보” 댓글을 남긴다.
- 빈 문서를 어디에 만들지, 결과 파일과 증거 링크는 어디에 붙일지 설명한다.
- 검토 요청과 최종 완료의 차이를 설명한다.

실제 회의 후 [회의록 양식](../templates/meeting-template.md)으로 결정·미해결·담당·기한을 기록합니다. 설명을 들었다는 이유만으로 설계·구축을 완료 처리하지 않습니다.

## 설명 전 PM·PL 준비
PM은 [날짜별 WBS](../01-planning/wbs/README.md)와 [착수 확인표](../01-planning/readiness.md)를 열어 둡니다. PL은 실제 자원·실행 계약·통신표의 미확정 사항을 확인합니다. 발표 11/16과 중간 마감일, 제출 조건을 구분하여 설명합니다.
