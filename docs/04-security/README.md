# 04 · 보안 문제·개선·재시험

**순서:** 문제와 시험 조건 → 개선 전 결과 → 개선 방법 → 적용 → 같은 조건의 재시험. 실제 결과가 없다면 “미수행” 표시.

| 문서 | 무엇을 적는가 | 파일 예 |
|---|---|---|
| [문제 확인](assessment.md) | 출발지·대상·입력·예상 결과·실제 로그와 영향 | `s01-m1-assessment.md` |
| [개선 방법](remediation.md) | 바꾼 정책·설정, 선택 이유·정상 서비스 영향 | `s01-m1-remediation.md` |
| [재시험](validation.md) | 전과 같은 조건의 결과, 정상 기능, 남은 위험 | `s01-m1-validation.md` |

| ID | 담당 | 확인할 문제 |
|---|---|---|
| S01 | M1 | 직원망에서 관리 서버 SSH 직접 접근 |
| S02 | M2 | 반복 SSH 인증 실패의 로그·경보 확인 |
| S03 | M3 | 서비스 구역에서 Kubernetes 관리 포트 노출 |
| S04 | M4 | 허가 없는 시험 계정의 테스트 백업 읽기 |
| S05 | M5 | 캐나다 직원망에서 VPN 경유 한국 DB 직접 접근 |

각 담당자가 자기 영역의 설정·시험 기록을 작성. M2는 공통 보안·로그 수집을 조율. 시험 범위는 승인된 격리 실습망 한정. [보안 문서 양식](../templates/security-assessment-template.md)과 [프로젝트 흐름](../../guide/FLOW.md) 참고.
