# 처음 시작하는 팀원 안내
[처음 화면](../README.md) · [작업 작성법](WORK_GUIDE.md)

## 설명을 듣기 전, 이 순서로
1. [프로젝트 흐름](PROJECT_FLOW.md)을 읽습니다. 무엇을 개선하고 어떤 증거로 확인하는지 이해합니다.
2. [내 역할](01-planning/team-roles/README.md)을 선택합니다. 첫 작업·협업 상대·산출물 위치를 확인합니다.
3. 역할 페이지의 **시작 Issue**를 엽니다. 목표·작업 체크리스트·완료 조건을 읽습니다.
4. [공용 링크](TEAM_LINKS.md)에서 Notion·저장소 접근을 확인합니다. 미등록이면 #6에 필요한 링크를 남깁니다.
5. 내 Issue에 “역할 확인 / 첫 작업 / 필요한 정보”를 짧게 남깁니다. 이 댓글은 수행 결과가 아니라 착수 확인입니다.

## 월요일 설명을 들은 후, 첫 작업
- 내 Issue 본문의 상태를 **진행 중**으로 바꿉니다.
- 구성도·시험 설계 초안을 작성합니다. [보안 양식](templates/security-assessment-template.md)을 사용하고 실제 시험 결과 칸은 **미수행**으로 둡니다.
- 기술서 양식을 Notion에 복제하고 작업하며 기록합니다. 아직 Notion이 없으면 승인된 팀 임시 공간에 기록하고 개설 후 연결합니다. 이를 기다리며 설계 작업을 멈추지 않습니다.
- 파일은 [폴더 지도](FOLDER_GUIDE.md)에 맞춰 저장합니다. 결과 파일·Notion URL을 내 Issue에 붙입니다.
- 완료 조건을 스스로 확인한 후 상태를 **검토 요청**으로 바꿉니다. 검토자가 확인하기 전 닫지 않습니다.

## 매일 작업 시작·종료
| 시점 | 내가 할 일 |
|---|---|
| 시작 | 내 열린 Issue와 새 검토 의견 확인 → 선행 조건 확인 → 다음 미체크 항목 선택 |
| 작업 중 | Notion에 설정 이유·실제 출력·문제 해결 기록, 재사용할 설정·코드는 GitHub 저장 |
| 막힐 때 | Issue 상태를 막힘으로 수정 → 증상·시도·도움 요청 기록 → 독립적으로 가능한 다음 작업 진행 |
| 종료 | 수행한 항목 체크 → 결과 링크·남은 일·다음 행동 한 번 기록 |
| 검토 후 | 보완하거나, 확인 근거를 남기고 완료 처리 → WBS의 다음 단계 Issue 확인 |

## 어디에 쓰는지 헷갈릴 때
- “지금 무엇을 하고 있지?” → **Issue**
- “무엇을 실제로 만들었지?” → **GitHub의 설정·코드·구성도·결과 문서**
- “어떻게 했고 왜 이렇게 했지?” → **Notion 기술서**
- “설치·시험이 실제로 됐는지 어떻게 알지?” → **로그·캡처·테스트 결과 링크**
- “다음은 무엇이지?” → **역할 페이지와 WBS**

글을 길게 쓰는 것이 목표가 아닙니다. 다른 팀원이 **다음 행동과 확인 근거를 찾을 수 있으면** 됩니다. [작성 예시 보기](examples/README.md)
