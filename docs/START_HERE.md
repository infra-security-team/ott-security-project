# 첫날은 이것부터 하세요
[처음 화면](../README.md) · [작성 방법](WORK_GUIDE.md)

## 1. 내 첫 작업을 엽니다
[유용수 #1](https://github.com/infra-security-team/ott-security-project/issues/1) · [윤서영 #2](https://github.com/infra-security-team/ott-security-project/issues/2) · [홍은서 #3](https://github.com/infra-security-team/ott-security-project/issues/3) · [박진혁 #4](https://github.com/infra-security-team/ott-security-project/issues/4) · [유은혜 #5](https://github.com/infra-security-team/ott-security-project/issues/5)

제목과 목표를 읽고 아래 세 줄을 댓글로 남깁니다. 아래는 작성할 빈칸이며 실제 수행 결과가 아닙니다.

```text
내가 맡은 일:
가장 먼저 할 일:
시작하려면 확인할 정보와 사람:
```

## 2. 내 Notion 기술서 한 곳을 준비합니다
[공통 양식](templates/technical-detail-template.md)의 제목들을 개인 페이지에 복사합니다.
오늘은 담당 범위, 구성 그림 초안, 필요한 정보부터 씁니다. 모든 칸을 첫날 채우지 않습니다.
팀 공간이나 권한이 없으면 [공동 준비 작업 #6](https://github.com/infra-security-team/ott-security-project/issues/6)에 알립니다. 기다리는 동안 초안은 팀이 정한 임시 공간에서 준비합니다.

## 3. 작업하고 기록합니다
설계·코드·설정 이유·실제 결과를 Notion에 이어 씁니다. 아직 실행하지 않은 내용은 계획, 시험하지 않은 결과는 미수행이라고 적습니다.
코드나 설정 파일을 실제로 만들었다면 GitHub에도 저장합니다. 업로드 방법은 [작업 가이드](WORK_GUIDE.md)를 따라갑니다.

## 4. 끝날 때 내 Issue를 갱신합니다
```text
오늘 한 일:
자료 링크: Notion / GitHub 파일이 있다면 그 링크
남은 일 또는 필요한 도움:
다음에 할 일:
```

수행한 항목만 체크합니다. 진행 중이면 상태를 진행 중으로, 도움 없이는 다음 작업이 불가능하면 막힘으로 적습니다.
결과를 모두 준비하면 검토 요청으로 바꾸고 함께 일하는 담당자에게 확인받습니다. 확인 후 완료로 바꾸고 Issue를 닫습니다.

**첫날 목표는 모든 구축 완료가 아닙니다. 내가 할 일·기록할 곳·도움받을 사람을 알고 설계 초안을 시작하는 것입니다.**

다음 단계는 [전체 작업 일정표](01-planning/wbs/README.md)에서 자기 이름의 다음 칸을 엽니다. 처음부터 38개 작업을 모두 읽을 필요는 없습니다.
